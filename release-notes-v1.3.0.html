Release notes

NIMELSSA Vault v1.3.0

v1.3.0 adds the verified-email access gate: any email address can be used, but it must be verified, and new students need admin approval before shared content opens. Reps can vouch for their level, admins make the final call, and Firestore rules enforce the gate on the server.

Latest release · Released 6 Nov 2026 · 4.6 MB download · ~18 MB installed before downloads · Android 8.0+ · 1 download

Access gate is live. Existing students without an approved profile will see the request screen. Staff accounts bypass the approval flag but still need a verified email. v1.2.0 installs update in place; v1.1.1 still needs a one-time uninstall.

Summary

v1.3.0 is a security and membership release. It adds a blocking access screen before the workspace, requires a verified Firebase Auth email, and routes new students through an access request that a class rep can vouch for and an admin can approve or reject. The same rules are enforced in Firestore, not only in the UI. Existing v1.2.0 installs update in place because the release signing key is unchanged.

Key Features

  • Verified-email gate: any email address is accepted, but Firebase Auth must confirm it before the app opens shared content.
  • Admin approval: new students submit their name, matric number, and level. A rep in the same level can vouch; only an admin can set the final approved flag.
  • Rep vouch queue: reps see requests for their own level and cannot vouch for themselves or approve the request outright.
  • Blocking access screen: unverified, pending, vouched, and rejected states each get a clear next action, including resend verification, notify a rep/admin, check status, and sign out.
  • Server-side enforcement: Firestore rules require email_verified plus approved == true for students, and staff roles bypass only the approval flag.
  • MLS matric check: signup and access requests require the department-shaped XX/XXPWXXX matric number.
  • Safer email changes: changing the account email now uses verification-before-update; the old address stays active until the new one is confirmed.
  • Offline reading preserved: downloaded files, the PDF reader, and the download-folder restore flow remain available after approval.

Installation

  1. If you are on v1.1.1 (debug-signed), uninstall it once. Back up anything you need first.
  2. Install NIMELSSA-Vault-v1.3.0.apk from the download card on this page.
  3. Open the app and sign in. Verify your email if the gate asks for it.
  4. Submit an access request with your name, matric number, and level. A rep can vouch; an admin approves.
  5. After approval, choose a Download location in Settings if you want saved files to survive a reinstall.
  6. v1.2.0 and later update in place; no uninstall is needed for this update.

Configuration

  • No new required keys and no google-services.json changes.
  • firestore.rules is the source of truth and was deployed for this release. It now gates shared reads and writes on verified email plus approval or a staff role.
  • Staff accounts need a verified email even though they bypass the student approval flag.
  • Existing students without approved = true must request access; there is no automatic backfill.
  • The download folder remains a user-selected Android SAF folder and is not a Firebase setting.

FAQ

Will updating to v1.3.0 wipe my downloads or saved data?

If you are on v1.2.0, no: it uses the same release signing key, so v1.3.0 updates in place. If you are still on v1.1.1 (debug-signed), Android requires a one-time uninstall, which clears app-private files. Firebase-backed courses, resources, proposals, and your profile return after sign-in; mirrored downloads can be restored by choosing the same Download location again.

Do I need a Unilorin email address?

No. Any email address can be verified and used. The actual MLS check is the access request: your matric number, a rep vouch from your level, and an admin's final approval.

What happens while my request is pending?

The access screen stays up and shared content remains locked. You can resend the verification email, notify a rep or admin, check status again, or sign out. If a rep vouches, the request moves to vouched and waits for an admin. A rejected request can be submitted again.

Is this release fully verified?

The access-gate build was device-tested end to end by the maintainer. The signed release APK passes the unit suite, the R8 release build, and apksigner signature verification in CI. The Drive folder scanner remains experimental, and no device-binding, watermarking, or access-log feature is included in this release.
