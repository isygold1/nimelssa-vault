Release notes

NIMELSSA Vault v1.3.2

v1.3.2 adds an in-app updater with a three-lifeline policy. The app checks for a newer versionCode on launch, offers three counted Later skips per release, then blocks on the next launch until the update is installed. Every download is verified before Android's installer opens.

Latest release · Released 7 Nov 2026 · 4.6 MB download · ~18 MB installed before downloads · Android 8.0+ · 0 downloads

In-app update. v1.3.2 is the first build with the in-app updater. Install it once from this page; later releases can be installed from Settings → APP UPDATE. v1.1.1 was debug-signed and still needs a one-time uninstall before a release-signed build can install.

Summary

v1.3.2 is the first release with the in-app updater. The app reads the public release.json feed, compares the remote versionCode with the installed build, and shows an update card when a newer build exists. The card appears automatically at launch and can also be opened from Settings → APP UPDATE.

Each release gets three counted Later skips. A skip only counts when you tap Later; opening the card, backgrounding the app, or failing a download does not consume a lifeline. After the third skip, the current session continues, but the next launch shows a blocking card with no Later, back, outside-tap, or close option. Installing the update or opening the release notes are the only actions. A new versionCode resets the count to three. Debug builds are never forced.

Before Android's installer opens, the app verifies the APK's SHA-256, package name, versionCode, and signing certificate. A failed check leaves the app on the update card with a retry option; it never hands an unverified file to the installer.

Key Features

  • Automatic check: a silent update check runs at launch and shows the card only when a newer versionCode is published.
  • Manual check: Settings → APP UPDATE shows the installed version, the latest version, and a Check for updates button.
  • Three lifelines: each release allows three counted Later skips; the count is stored per versionCode and resets when a new release is published.
  • Blocking forced card: after the third skip, the next launch cannot be dismissed with Later, back, outside tap, or a close button. Only Update now and the release notes link remain.
  • Verified install: SHA-256, package name, versionCode, and signing certificate are checked before the installer is invoked.
  • Resume support: a downloaded and verified update can be resumed from Settings without downloading it again.
  • Debug safety: debug builds always report at least one lifeline and cannot install the release APK.
  • In-place update: v1.3.1 and later use the same release signing key, so no uninstall is needed.

Installation

  1. If you are on v1.1.1 (debug-signed), uninstall it once. Back up anything you need first.
  2. Install NIMELSSA-Vault-v1.3.2.apk from the download card on this page. This is the first build with the in-app updater; later releases can be installed from Settings → APP UPDATE.
  3. Android may ask you to allow installs from NIMELSSA Vault the first time. Grant it once; the permission is scoped to this app.
  4. Open the app and sign in. Verify your email and complete the access gate if prompted.
  5. After approval, choose a Download location in Settings if you want saved files to survive a reinstall.
  6. v1.3.1 and later update in place; no uninstall is needed for this update.

Configuration

  • No new required keys and no google-services.json changes.
  • The update feed is the public release.json on this site; no GitHub account is required to check, download, or read the notes.
  • Android's install-unknown-apps permission is requested the first time the app hands an APK to the installer. It is app-scoped and can be revoked in Android settings.
  • Firestore rules, the access gate, and the Drive API key are unchanged from v1.3.1.
  • The Windows desktop client is a separate read-only build with its own Drive key and is not affected by this release.
  • The download folder remains a user-selected Android SAF folder and is not a Firebase setting.

FAQ

Will skipping three times lock me out of the app?

No. After the third Later, the current session continues. On the next launch the update card is blocking: there is no Later, back, outside tap, or close button. Update now or open the release notes. The update installs in place, so your Firebase data and app-private files are preserved.

Will updating wipe my downloads or saved data?

No. v1.3.1 and later use the same release signing key and update in place. If you are still on v1.1.1 (debug-signed), Android requires a one-time uninstall, which clears app-private files. Firebase-backed courses, resources, proposals, and your profile return after sign-in; mirrored downloads can be restored by choosing the same Download location again.

Can I still use the app offline?

Yes, until a forced update is pending. The launch check fails silently when offline and never blocks by itself. If you have already used all three skips, installing the update needs a connection; after that, offline reading works as before.

Do I need a GitHub account to update?

No. The app reads a public release.json feed and downloads the APK directly. This site's download page and release notes also work without an account.

Does this release affect the Windows desktop client?

No. The desktop client is a separate read-only build with its own Drive key and configuration. This release only changes the Android app.

Is the updater fully verified?

The release APK passes the unit suite, the R8 release build, and apksigner verification in CI. The app also checks SHA-256, package name, versionCode, and the signing certificate before install. The in-app handoff uses Android's standard package installer; it has not been exercised on every OEM skin, so if the installer prompt does not appear, install the APK from this page.
