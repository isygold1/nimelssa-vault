Release notes

NIMELSSA Vault v1.3.3

v1.3.3 is a bug-fix release: pinned files now survive clearing the Recently opened strip. The X clears unpinned history only, pinned files stay put, and the eight-entry cap is unchanged.

Latest release · Released 9 Nov 2026 · 4.6 MB download · ~18 MB installed before downloads · Android 8.0+ · 0 downloads

Bug fix release. v1.3.3 keeps the install path from v1.3.2: install it once from this page, and later releases arrive through Settings → APP UPDATE. v1.1.1 was debug-signed and still needs a one-time uninstall before a release-signed build can install.

Summary

v1.3.3 is a bug-fix release. Clearing the Recently opened strip on the Workspace screen used to wipe pinned files along with the normal history. Pinning a file is meant to survive that button, and now it does: the X removes unpinned entries and leaves every pinned file exactly where it was.

Unpinned history is still trimmed to eight entries, so the strip keeps its size cap and newly opened files continue to push out the oldest unpinned ones. Pinned files are never trimmed and never count against that cap.

Nothing else changes. The in-app updater, the three-lifeline policy, and the SHA-256, package name, versionCode, and signing-certificate checks before install all behave exactly as they did in v1.3.2.

Key Features

  • Pinned files survive: the X on the Recently opened strip clears only unpinned history; pinned files stay pinned and stay visible.
  • Same eight-entry cap: unpinned history is still trimmed to eight entries, and pinned files do not count towards it.
  • Unchanged updater: automatic check at launch, manual check from Settings → APP UPDATE, and three counted Later skips per release.
  • Verified install: SHA-256, package name, versionCode, and signing certificate are checked before the installer is invoked.
  • In-place update: v1.3.1 and later use the same release signing key, so no uninstall is needed.

Installation

  1. If you are on v1.1.1 (debug-signed), uninstall it once. Back up anything you need first.
  2. Install NIMELSSA-Vault-v1.3.3.apk from the download card on this page, or update from Settings → APP UPDATE inside the app.
  3. Android may ask you to allow installs from NIMELSSA Vault the first time. Grant it once; the permission is scoped to this app.
  4. Open the app and sign in. Verify your email and complete the access gate if prompted.
  5. Pinned files, saved resources, and a chosen Download location carry over; updating from v1.3.1 or later does not clear app data.

Configuration

  • No new required keys and no google-services.json changes.
  • The update feed is the public release.json on this site; no GitHub account is required to check, download, or read the notes.
  • Android's install-unknown-apps permission is requested the first time the app hands an APK to the installer. It is app-scoped and can be revoked in Android settings.
  • Firestore rules, the access gate, and the Drive API key are unchanged from v1.3.2.
  • The Windows desktop client is a separate read-only build with its own Drive key and is not affected by this release.
  • The download folder remains a user-selected Android SAF folder and is not a Firebase setting.

FAQ

Does clearing Recently opened still remove pinned files?

No. The X clears only unpinned history. Pinned files stay pinned, stay in the strip, and are not counted towards the eight-entry cap.

Will skipping three times lock me out of the app?

No. After the third Later, the current session continues. On the next launch the update card is blocking: there is no Later, back, outside tap, or close button. Update now or open the release notes. The update installs in place, so your Firebase data and app-private files are preserved.

Will updating wipe my downloads or saved data?

No. v1.3.1 and later use the same release signing key and update in place. If you are still on v1.1.1 (debug-signed), Android requires a one-time uninstall, which clears app-private files. Firebase-backed courses, resources, proposals, and your profile return after sign-in; mirrored downloads can be restored by choosing the same Download location again.

Can I still use the app offline?

Yes, until a forced update is pending. The launch check fails silently when offline and never blocks by itself. If you have already used all three skips, installing the update needs a connection; after that, offline reading works as before.

Do I need a GitHub account to update?

No. The app reads a public release.json feed and downloads the APK directly. This site's download page and release notes also work without an account.

Does this release affect the Windows desktop client?

No. The desktop client is a separate read-only build with its own Drive key and configuration. This release only changes the Android app.

Is the updater fully verified?

The release APK passes the unit suite, the R8 release build, and apksigner verification in CI. The app also checks SHA-256, package name, versionCode, and the signing certificate before install. The in-app handoff uses Android's standard package installer; it has not been exercised on every OEM skin, so if the installer prompt does not appear, install the APK from this page.
