Summary

v1.2.0 is the first release-signed build of NIMELSSA Vault. It fixes the Activity Result crash that broke the storage folder picker, adds a user-chosen download folder that survives reinstalls, and gives admins a safe way to remove duplicate cards from a course shelf. It also includes reader chrome polish, cross-level general textbooks, and proposal/notification hardening.

Key Features

  • Download location that survives a reinstall: choose a folder in Settings or from the Downloads prompt; saved files are mirrored there and restored when the folder is picked again.
  • Admin duplicate cleanup: cards for the same Drive file, or for two uploads with identical MD5s, are flagged on the course shelf. An admin can delete the duplicate card for everyone without deleting the Drive file.
  • Activity Result crash fixed: androidx.fragment:fragment:1.6.2 overrides the old transitive version, so the storage folder picker and other Activity Result launchers no longer crash.
  • Reader chrome: the toolbar and bottom navigation hide as you scroll down and return when you scroll back up.
  • General textbooks across levels: a textbook with a blank course code and “All Levels” is saved once and appears on every level shelf.
  • Security hardening: proposal links are validated and notification spoofing paths are closed.

Installation

  1. If you are on v1.1.1 (debug-signed), uninstall it once. Back up anything you need first.
  2. Install NIMELSSA-Vault-v1.2.0.apk from the release assets (the download card on this page).
  3. Sign in. Firebase-backed courses, resources, proposals, and your profile return from Firestore.
  4. Choose a Download location in Settings (or on the first save prompt) so future downloads survive a reinstall.
  5. Later release-signed builds update in place; no uninstall is needed.

Configuration

  • No new required keys or google-services.json changes.
  • firestore.rules changed in this release branch and must be published in the Firebase Console if the new rules are not already live.
  • The download folder is a user-selected Android SAF folder; the app writes mirrored copies under per-course folders. It is not a Firebase setting.

FAQ

Will installing v1.2.0 wipe my downloads or saved data?

If you are coming from v1.1.1, yes for local data: v1.1.1 was debug-signed, so Android requires a one-time uninstall, which clears app-private files. Firebase-backed courses, resources, proposals, and your profile return after sign-in. Downloads made in v1.2.0 can be mirrored to a folder you choose and restored after a later reinstall.

How do I remove a duplicate card?

Open the course as an admin. Cards that are the same file as another card on that shelf show a red “Same file as another card on this shelf” warning and a “Delete this duplicate” button. Confirm the deletion; it removes the catalog card for everyone but leaves the Drive file untouched. The check is per course shelf and only works when the cards have a Drive file ID or MD5 checksum.

Where do my downloads go, and how do I keep them?

Saved files live in the app's private storage by default, and are deleted if you uninstall. Choose a Download location in Settings (or from the Downloads screen prompt) to also mirror them into a folder you control. After a reinstall, choose the same folder again and the app restores the mirrored copies.

Is this release fully verified?

The ff-test debug build with these fixes was device-tested, including duplicate deletion. The signed release APK passed the unit suite (52/52), the R8 release build, and apksigner signature verification, but it was published without a separate on-device smoke test. The Drive folder scanner remains experimental, and duplicate cleanup is limited to one course shelf and cards with a file ID or MD5.
